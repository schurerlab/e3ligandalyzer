Researcher-facing data model

Database schema and objects

The Ligandalyzer database is organized around structure-linked recruiter instances rather than chemistry-only rows. The same ligand can therefore appear in more than one recruiter record when it is observed in distinct ligase, structure, or variant contexts. This page summarizes the main public objects exposed by the current SQLite-backed resource and download tables.

Core identifiers and cross-table keys

LR recruiter code

RECRUITER_CODE is the main public recruiter identifier. It points to a curated recruiter/structure instance rather than only a chemical name.

Instance key

Instance_Key preserves a composite structural identity across ligase, PDB, ligand code, and variant context, making duplicate handling and traceability explicit.

PDB-linked identity

pdb_id, Ligand, Residue_ID, and Variant are used together to anchor recruiter rows to a resolved structural context.

Scaffold-linked identity

Scaffold_ID, Original_Scaffold_ID, Scaffold_Hash, and unified scaffold fields support cross-record scaffold comparison.

Recruiter records

Recruiter records are primarily assembled from Ligand_Instance_Recruiter_Codes, Ligase_Ligand_Metadata, Ligase_Chemical_Descriptors, Recruiter_Code_Crosswalk, and related mapping tables. The same public ligand page combines several of these objects into one record view.

FieldMeaning
RECRUITER_CODECanonical LR identifier used in URLs, downloads, descriptors, SASA summaries, and scaffold mappings.
LigandOriginal ligand/component identifier from the structure, typically a short PDB-style ligand code.
LigaseCurated E3 ligase context for the recruiter instance.
pdb_id / PDB_FileStructure identifier and resolved structure asset used for traceability and downloads.
SMILES / Canonical_SMILES2D structural representations used for descriptor generation, deduplication logic, rendering, and export.
Formula, InChI, InChIKeyChemical identity fields when available from the metadata-cleanup workflow.
QED, LogP, TPSA, HBA, HBDDescriptor values used for filtering, ranking, and chemical triage.
Scaffold_IDScaffold assignment linking the recruiter to scaffold dashboards and scaffold-level summaries.
Source_SDF / download assetsFile-level references used to expose public PDB, SDF, ZIP, and manifest downloads.
External linksRecruiter pages may additionally resolve to PDB, ChEMBL, or related external resources when present in the frontend integration.

Ligase records

Ligase-level views are assembled from scaffold, recruiter, and ELiAH-linked expression sources rather than a single narrow ligase table. In practice, the ligase explorer and expression pages expose a derived ligase object with summary counts, associated structures, scaffold diversity, and tissue-expression context.

FieldMeaning
LigasePrimary ligase name used throughout recruiter, scaffold, and download routes.
gene_name or ELiAH query termExpression-atlas gene query label when the ligase can be mapped into the ELiAH integration layer.
structure_countDerived count of resolved recruiter-bound structures associated with that ligase.
recruiter_countDerived count of recruiter records linked to that ligase.
scaffold_countDerived count of scaffold identities linked to that ligase.
expression atlas integrationWhen available, ELiAH-backed expression, enrichment, and tissue search views provide a complementary biological context layer.

Scaffold records

Scaffold objects are built from the recruiter-to-scaffold map and the scaffold summary tables exposed by the live application. These tables support scaffold dashboards, scaffold detail pages, and full-network views.

FieldMeaning
Scaffold_IDPublic scaffold identifier used by scaffold routes and summary tables.
Scaffold_SMILES / Murcko_SMILESScaffold-level structure representations used for display and grouping.
RECRUITER_CODE groupRecruiter records associated with the scaffold.
Ligase groupLigases carrying that scaffold or unified scaffold family.
Recruiter_CountHow frequently a scaffold appears in recruiter records.
Scaffold_ClassHigher-level chemical scaffold family label when assigned by the scaffold workflow.
Supercluster_Key / unified scaffold fieldsAdvanced scaffold-clustering layer used when cross-scaffold grouping is available in the current database snapshot.

SASA summary records

The Ligase_Ligand_SASA_summary table stores recruiter-level solvent accessibility in the bound structural context.

FieldMeaning
SASA_in_complex_A2Total solvent-accessible surface area for the bound recruiter in the complex.
%ExposedFraction of the recruiter remaining solvent-accessible in the bound context.
%BuriedComplementary buried fraction in the same bound context.
Exposed_atomsCount of atoms with measurable solvent exposure in the current summary logic.
Recruiter_ClassRecruiter-type label used by some dashboards and filters.
MW_Status / WarningsCompleteness or caution fields preserved when a recruiter row requires annotation.
record completenessThe live snapshot can be assessed by checking whether exposure summary fields are present; release notes should be used for release-level completeness summaries.
The public release does not currently expose a separate categorical field named Exposure_Class in the SASA summary table. Instead, atom-level and summary-level exposure are represented through continuous SASA values and aggregate exposed/buried fractions.

Atom-level SASA records

The Ligase_Ligand_SASA_atoms table is the atom-resolved layer used by the recruiter page and structure-aware solvent exposure views.

FieldMeaning
atom_idPDB-linked atom serial used for structural traceability.
exact_atomAtom label, such as C7, O2, or N3, as represented in the curated structure.
atom_typeElement assignment used for visualization and interpretation.
Exposure_A2Continuous solvent exposure value in square angstroms at atom resolution.
is_heavy_atomHeavy-atom indicator used by heavy-atom SASA summaries and QC checks.
x, y, zCoordinates retained for atom mapping and visualization context.
attachment relevanceThe public site uses these atom-level exposure values to support attachment-vector inspection, but an explicit attachment-score field is not currently exposed in the live table schema.

Download manifest and file mapping

The download layer is designed so that public files can be mapped back to recruiter, ligase, and table objects without guessing. Use the human-readable download manifest as the public index, and the raw JSON manifest for scripted access when you need release-aware download provenance.

File typeHow it maps to records
JSONAPI endpoints return recruiter, ligase, scaffold, manifest, and ELiAH-linked records in structured web-consumable form.
CSVTable exports expose whitelisted SQLite tables for spreadsheet, pandas, or R workflows.
PDBStructure-linked recruiter assets retain ligase and PDB context for direct modeling or viewer reuse.
SDFRecruiter-linked structure files support cheminformatics workflows and compound-level export.
ZIPLigase, recruiter, and all-asset bundles package multiple PDB/SDF files into one transfer unit.
Bundles and manifestsFor citation or reproducibility, pair a downloaded bundle with the matching release note, manifest, and schema version used at the time of analysis.
