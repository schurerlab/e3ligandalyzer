About the resource

These questions explain what the resource is, what Version 1 means, and how to frame its intended scope.

What is E3 Ligase Ligandalyzer?
E3 Ligase Ligandalyzer is a structure-first, recruiter-focused database resource for exploring curated E3 ligase recruiter records, ligand views, scaffold context, SASA-linked exposure information, and release-aware downloads.
What is a recruiter?
In this resource, a recruiter is the ligand component used to engage an E3 ligase in a degrader or related targeted-protein-degradation context. The site keeps structural context visible rather than collapsing everything into one purely chemical record.
What does “structure-first” mean?
It means the public resource is organized around curated structure-linked recruiter instances, associated structural files, SASA context, and release-aware provenance, not just a flat list of names or SMILES strings.
Is this intended to be exhaustive?
No. Version 1 should be interpreted as a curated snapshot, not an exhaustive claim covering every literature report or every possible E3 ligase recruiter context. Future releases may expand coverage.
What is Version 1?
Version 1 is the first public database release for this resource. It should be treated as the curated Version 1 snapshot described on the Release page and paired with the public manifest, schema, and methods pages when documenting reproducible use.

Data and curation

How are E3 ligase and recruiter structures selected?
The public site sits on top of a curated structural workflow described in the Methods page. Structure-linked evidence, recruiter interpretation, SASA context, scaffold mapping, and release-aware provenance are all part of that curation process.
Why might some molecules look peptide-like or incomplete?
Some records may need follow-up curation when a recruiter appears fragment-like, peptide-like, or only partially extracted from a larger biological or medicinal-chemistry context. If you suspect that, use Report Issue.
Why might BRD or BIRD-like molecules appear?
A curated structure-first workflow can surface molecules that need further interpretation or future filtering. The presence of a BRD or BIRD-like record does not automatically mean it is final or complete; it may reflect the current state of a structure-linked curation pass.
What should I do if a ligand looks like a fragment of a larger molecule?
Use /report-issue and include the recruiter code, ligase, PDB context, page URL, and your rationale or supporting citation. That is the preferred workflow for suspected incomplete extraction.
How are duplicate recruiters handled?
Duplicate-looking records are not always simple errors. Some are preserved because they represent distinct structural contexts, variants, poses, or curated instance mappings. When a duplicate looks suspicious rather than intentionally distinct, report it for review.
How are scaffold assignments interpreted?
Scaffold assignments are intended as a useful structural organization layer, not an immutable truth statement. They may evolve in future releases as curation and clustering improve. See the Schema page and scaffold dashboards for context.
How often will the database be updated?
The public release language currently describes an annual review and update cadence. Future releases may expand ligase coverage, recruiter mappings, scaffold annotations, and SASA-linked assets after review and curation.

Ligand and recruiter pages

What does an LR code mean?
An LR code is a curated recruiter-instance identifier used to preserve structure-level context. It helps distinguish recruiter occurrences across ligases, PDB entries, variants, and related structural settings.
What do the 2D and 3D views show?
The ligand page combines a 2D depiction, a 3D structure view, and SASA-linked overlays to help interpret recruiter geometry, structure context, and exposure. These visualizations are aids for interpretation rather than guarantees of downstream design success.
What does the SASA map mean?
The SASA map highlights solvent exposure for atoms or regions in the current recruiter context. It is intended as a screening aid for interpretation and design triage, especially when thinking about accessible attachment regions.
How should I interpret exposed atoms?
Exposed atoms can suggest candidate attachment regions, but SASA alone does not guarantee a good linker attachment site. Medicinal chemistry judgment, geometry, permeability, and downstream ternary-complex considerations still matter.
Why might a structure, SVG, SDF, or SASA view be missing?
Some recruiter records may have incomplete linked assets in the current snapshot. The site surfaces those cases through missing-data pages rather than silently hiding them. Those gaps can be reported for future curation.
How do I report a ligand-page issue?
Use the `Report Issue` button on the ligand page or go directly to /report-issue. That workflow is designed specifically for structured database and ligand-page problem reports.

API and downloads

What is the API base URL?
The public API base URL is https://e3ligandalyzer.com/api. The full route guidance and examples live on the API Reference page.
How do I use export BASE="https://e3ligandalyzer.com/api"?
Run that command in your terminal first, then use the documented `curl` or Python examples that refer to $BASE. This keeps copy-paste commands aligned with the canonical public API host.
Why did curl say “No host part in the URL”?
That usually means your BASE variable is empty or was not exported in the current shell. Re-run the export command from the API page before trying the example again.
What is the difference between the human-readable manifest and the raw JSON manifest?
The human-readable manifest is intended for researcher review and citation-friendly browsing, while the raw JSON manifest is designed for scripted or programmatic workflows.
How do I download all structures for a ligase?
Use the documented download endpoints on the API Reference page and pair the output with the Download Manifest and Release page for reproducibility context.
How should I cite or record downloaded data?
Record the Version 1 release context, the matching manifest, and the relevant methods/schema references used at the time of download. The site should be treated as a curated release-aware resource rather than a context-free file dump.

PROTAC and design workflow

How does the PROTAC Builder handoff work?
The ligand page can hand recruiter context into the linked PROTAC Builder workflow so you can continue into design-oriented steps. It is meant as a convenience bridge between resource exploration and downstream design tooling.
Does exposed SASA guarantee a good linker attachment site?
No. SASA is a screening aid, not a guarantee. Attachment quality still depends on chemistry, geometry, ternary-complex behavior, linker trajectory, and broader design constraints.
Can I use this directly for ternary-complex prediction?
Not by itself. The resource supports recruiter selection and context inspection, but ternary-complex prediction still requires additional modeling, scoring, and design workflows.
How should I combine this with Warhead Hunter or other modules?
A common pattern is to use Ligandalyzer to inspect recruiter context, identify exposure-aware design hypotheses, and then move into Warhead Hunter, PROTAC Builder, or other modeling tools for target-side ligand discovery and degrader assembly.

Reporting and support

When should I use Report Issue?
Use Report Issue for suspected database, curation, asset, ligand-page, visualization, or download problems such as incomplete molecules, missing SASA, wrong recruiter codes, duplicates, or broken routes.
When should I use Feedback?
Use Feedback for usability, documentation, product experience, readability, workflow, or feature-request comments that are not primarily about database correctness.
When should I use Contact?
Use Contact for broader author-facing communication, including interpretation questions, collaboration ideas, manuscript or resource-development discussions, and general project communication.
How can I submit new data?
Use Submit Data / Contribute for additions, future release candidates, and structured correction submissions that should be reviewed for inclusion.
