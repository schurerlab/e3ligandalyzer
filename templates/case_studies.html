Case study 1

CRBN recruiter selection by QED and SASA

Use the Explorer when the goal is to identify CRBN-linked recruiters that balance tractable physicochemical properties with visible solvent exposure that may support linker design.

Research question

Which CRBN recruiter records combine reasonable drug-likeness with exposed structural features worth inspecting for linker attachment?

Pages and tools used

Explorer filters, individual recruiter pages, SASA views, and the API descriptor routes when batch export is needed.

Suggested workflow

Filter the Explorer to CRBN, raise the QED threshold, open candidate recruiter pages, and compare atom-level SASA overlays before selecting follow-up structures.

Expected interpretation

Prefer records that remain chemically plausible for your use case and expose atoms in regions that do not obviously destroy the recruiter-binding core.

Explorer Metric glossary SASA schema
Caveat: exposed atoms are a screening clue, not a guarantee of productive linker growth or ternary-complex performance.
Case study 2

VHL versus CRBN scaffold diversity comparison

This workflow is useful when deciding whether a ligase space is dominated by one recurring chemotype or supported by a broader recruiter scaffold landscape.

Research question

Does one ligase appear structurally concentrated while the other spans a broader scaffold family distribution?

Pages and tools used

Scaffold dashboard, scaffold detail pages, scaffold network view, and scaffold summary API routes.

Suggested workflow

Inspect scaffold summaries by ligase, review scaffold frequency views, and open representative scaffold pages to see which LR codes and ligases contribute to the dominant chemotypes.

Expected interpretation

Broader scaffold spread suggests more chemotype diversity; a concentrated scaffold profile suggests stronger dependence on a smaller recruiter family.

Caveat: scaffold totals and clustering should be interpreted alongside the release page, because formal archived release manifests are still being finalized.
Case study 3

Identifying exposed atoms for linker attachment

Recruiter pages are designed to support attachment-vector triage by combining 2D SASA overlays, 3D structure context, and atom-resolved exposure tables.

Research question

Which atoms on a recruiter appear solvent-exposed enough to justify linker exploration without immediately disrupting the known binding core?

Pages and tools used

Recruiter pages, SASA atom overlays, 3D viewer, and the full SASA API payload for export-driven workflows.

Suggested workflow

Open one LR page, toggle the SASA views, inspect per-atom exposure, then compare multiple recruiter instances of the same underlying ligand when available.

Expected interpretation

Look for recurring exposed regions across instances rather than relying on a single conformation when the same ligand is observed in multiple structures.

Ligand-page guide Atom-level SASA schema SASA methods
Caveat: the current public schema exposes continuous atom-level SASA values, but not a formal public attachment score. Final attachment decisions still require medicinal-chemistry judgment.
Case study 4

Exporting recruiter PDB and SDF assets into PROTAC Builder

Once a recruiter has been shortlisted, the fastest next step is often to move its structural assets into a modeling environment rather than manually reconstructing them.

Research question

How do I move from a recruiter page to a reproducible file bundle for modeling, docking, or PROTAC Builder transfer?

Pages and tools used

Recruiter pages, API download manifest, ligase ZIP endpoints, recruiter ZIP endpoints, and PROTAC Builder handoff controls.

Suggested workflow

Resolve a recruiter code, confirm its structure context, download PDB/SDF assets from the recruiter or ligase bundle endpoints, and preserve the manifest alongside the files used in modeling.

Expected interpretation

The manifest and release page together provide the provenance needed to describe which exact public resource state supported a downstream design session.

Download API Release notes Manifest
Caveat: for manuscript-quality reproducibility, keep the corresponding release note and manifest with the exported structures.
Case study 5

Finding tissue-compatible E3 ligases with the ELiAH expression atlas

The ligase page integrates structure-centric recruiter data with an expression-atlas workflow so users can connect chemistry and biological context.

Research question

Which ligases in the curated resource also appear biologically relevant in tissues or expression contexts related to my project?

Pages and tools used

Ligase index and ELiAH search panels, ligase detail summaries, and recruiter or scaffold views for shortlisted ligases.

Suggested workflow

Start in the ligase page, query tissue or gene-expression context, shortlist biologically relevant ligases, then move back into recruiter and scaffold views to inspect available chemotypes.

Expected interpretation

Expression support does not replace structural suitability, but it can help prioritize which ligase systems deserve deeper recruiter and linker design effort.

Caveat: expression context is complementary metadata. It should be interpreted alongside structure availability, recruiter chemistry, and project-specific biology.
