Community curation

Submit data and contribute

E3 Ligase Ligandalyzer is designed as a curated database resource, so useful contributions are welcome when they improve structure coverage, recruiter annotation, scaffold interpretation, or missing-data resolution. Submissions are reviewed before inclusion so the public resource stays traceable, release-aware, and scientifically coherent.

Email the maintainers GitHub profile Report missing structure context Read curation methods

Accepted contribution types

  • Report missing structures or incomplete structure-linked assets.
  • Suggest new E3 ligases or substrate-receptor systems for future curation.
  • Submit new recruiter records or correct existing recruiter annotations.
  • Propose scaffold annotations, scaffold regrouping, or structure-level metadata fixes.
  • Share release, provenance, or literature notes that improve traceability.

Required metadata for a useful submission

  • E3 ligase name
  • Recruiter or ligand name
  • PDB ID or other structural source
  • SMILES, SDF, or PDB file when available
  • Citation, DOI, or source link
  • Notes on ligand chain, residue, atom, or recruiter-code mapping
  • Submitter contact information for follow-up questions

Report missing structures

If a recruiter page, structure file, or SASA asset appears incomplete, send the recruiter code, PDB context, and the exact page or file path that failed. The site’s missing-data pages are useful starting points because they preserve context for follow-up curation.

Missing data page Missing recruiter page

Suggest new ligases

When proposing a new E3 ligase, include the preferred ligase or gene name, candidate structures, and why the system belongs in a recruiter-focused E3 resource. Structure-linked evidence is more useful than a name alone.

Submit recruiter corrections

Recruiter submissions are strongest when they explain the intended ligand identity, structure source, residue code, and whether the change affects duplicate handling, LR-code assignment, or scaffold mapping.

Submit scaffold or structure annotations

Scaffold corrections, unified scaffold notes, or structure-quality observations are welcome when they are tied to concrete recruiter codes, scaffold IDs, or structure files already visible in the public resource.

Validation and review policy

Submissions are reviewed before public inclusion. The current site and companion curation repositories emphasize ligase identity validation, recruiter-linked structure context, duplicate handling, and release-aware provenance rather than automatic ingestion without review.

Inclusion is not immediate or guaranteed. Records may be held for clarification, normalized into the existing schema, or deferred until they can be incorporated into a reproducible release pass.

How to send a submission

The current public submission paths are the project contact email and the public GitHub pathway already linked from the site. If you open a GitHub issue or send email, include enough structural detail that the maintainers can connect your submission to the current curation pipeline.
